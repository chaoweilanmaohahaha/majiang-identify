# 设计：听牌判定前端界面

## Context

uni-app（Vue3 + Vite + TS）微信小程序，启动页为 `src/pages/index/index.vue`。核心判定模块 `src/core/mahjong/` 已提供 `getListeningTiles`（13 张暗牌 → 听口）、`tileName`、`PLAYABLE_KIND_COUNT`（31）等。界面不依赖图片素材，全部 CSS 自绘。动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 改造 index 页：13 张暗牌选择 + 判定 + 听口/未听牌展示。
- 麻将牌桌风格视觉，纯 CSS 自绘，无素材依赖。

**Non-Goals:**
- 副露/花牌输入、胡牌展示、番数、对局流程。

## Decisions

### 1. 页面结构（单页，`src/pages/index/index.vue` 内实现，不新增路由）
- 顶部：标题与状态提示区（已选张数 / 判定状态）。
- 中部"桌面"：绿色呢绒背景圆角面板，展示已选 13 张牌位（空位以虚线格占位），点击已选牌可移除。
- 下部：选牌区，按 万/条/筒/风 四组平铺，每组 9/9/9/4 个牌位；牌位显示牌名（如"3万"），并显示该种已选数（如 x2 角标）；达到 4 张或总数 13 张时禁选（置灰）。
- 底部：清空与"听牌判定"按钮；结果区（听口牌面列表或未听牌提示）。
- 理由：单页完成输入+结果展示，交互链路最短；分组符合麻将习惯。

### 2. 状态与逻辑（响应式，不引入状态库）
- `selected: Map<number, number>`（牌编码 → 数量），用 `ref` 包裹的数组实现（长度 31 的计数数组），避免 Map 响应式坑。
- 总数 `total = sum(counts)`；`total === 13` 时按钮可用。
- 判定：`getListeningTiles({ concealed, melds: [], flowers: [] })`；用 `try/catch` 包住（虽然 UI 已保证 13 张，仍防输入错误）。
- 听口数组（0-30 编码）经 `tileName` 转牌面展示；听口为空 → 未听牌提示。
- 理由：状态简单，无需 pinia；核心逻辑直接复用已归档能力。

### 3. 牌面组件（内联，不注册全局组件）
- 用普通 `view` + CSS 类实现三种尺寸的牌：选牌区小牌、桌面上大牌、听口展示中牌。
- 牌面样式：白底、圆角、细边框、阴影；数牌左上/右下角标数字，中央大字；风牌中央显示"东南西北"文字。
- 红中/发财/白板不出现（敲麻中为花牌，不参与输入）。
- 理由：文字自绘无需素材；统一 CSS 变量控制配色（桌面绿、牌面白、文字黑红）。

### 4. 视觉主题（麻将牌桌）
- 页面背景深木色（#3a2f23 系）；桌面面板绿色呢绒渐变（#1d7a45 → #16603a）+ 深色边框 + 内阴影；按钮用麻将感圆角（琥珀/深绿）。
- 结果区高亮：听牌时听口牌面以红色文字/描边突出；未听牌用灰色提示文案。
- 理由：符合"麻将牌桌"要求，避免引入图片。

### 5. 平台与兼容
- 使用 `rpx` 尺寸单位适配屏幕；不依赖 Canvas、不依赖第三方组件。
- `src/pages.json` 无需改动（index 已是首页），仅改 navigationBarTitleText 为"听牌判定"。

## Risks / Trade-offs

- [微信小程序 `view` 上 CSS 渐变/阴影兼容] → 渐变与 box-shadow 在 mp-weixin 支持良好；若个别样式异常，退化为纯色。
- [31 个牌位在小屏拥挤] → 小牌位用网格布局，每行 9 个，字号随 rpx 缩放。
- [判定为同步纯函数，量小] → 无性能风险，直接在主线程执行。
